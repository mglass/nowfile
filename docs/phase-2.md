# Phase 2: sources and subscriptions

Goal: a web-only user's page updates itself from a calendar, readers can follow a page without an account, and terminal users can install `plan` without a Go toolchain. Read `docs/brief.md`, `docs/format.md`, `docs/phase-1.md`, and `AGENTS.md` first. Phase 1 is live at nowfile.org; everything here lands on that server.

Decided 2026-10-14: no Last.fm. Listening arrives with the Mac agent (phase 4), which reads now-playing directly. Nothing in this phase touches the Listening slot.

## Deliverables

1. Sources model. A `sources` table (id, user_id, kind, config JSON, enabled bool, last_run, last_error, created). One source per kind per user. Each source has a preview: the exact line it would publish now, computed on demand, shown on the account page before the user can switch it on. Principle 1 of the brief: nothing is published from a source the user has not switched on and previewed.
2. Calendar source. Kind `calendar`, config holds one ICS URL (webcal:// accepted and rewritten to https://). A background runner fetches every enabled calendar every 5 minutes with a 10 second timeout, 1 MB cap, conditional GET with ETag and Last-Modified, and writes the `Calendar` slot through the one slot-write path with source `calendar`. The line is busy state only: `Busy until 15:00` in the user's time zone, `until` set to the event end, and the slot cleared when nothing is current. Never the event subject. All-day events and events marked transparent (`TRANSP:TRANSPARENT`) or free do not count. Back-to-back and overlapping events merge into one busy span. Recurring events expand correctly for at least daily and weekly `RRULE` with `UNTIL`, `COUNT`, `BYDAY`, and `EXDATE`; anything the parser cannot expand is logged and skipped. The user's time zone comes from a new `tz` column on `static` (IANA name, set from the browser on the account page, editable). Fetch failures keep the last slot until its own `until` passes, then it expires on its own; three failures in a row set `last_error` and show it on the account page. The runner is in the same binary, starts with the server, and skips cleanly when there are no sources.
3. Account page: a Sources section. Add a calendar: paste URL, see the preview (the line, or "Nothing current, next busy at ..."), then Enable. Disable, edit URL, remove. Show last run and last error. Time zone field.
4. Subscriptions. Readers follow a page without an account. `GET /{name}.rss`: RSS 2.0 with one item per Status or Calendar change (title the headline line, pubDate the set time, guid from user, key, and set time), last 50 changes, cached for a minute. Email: a form on the public page taking an address, double opt-in (confirmation mail with a one-use link, 24 hour expiry), then one digest a day per subscriber at 08:00 in the page owner's time zone (`static.tz`, UTC when unset): the current headline line at the top, then every Status and Calendar change from the previous day (08:00 to 08:00 local) in order with local times. No mail on a day with no changes. A digest goes out once per subscriber per local day, across restarts. Every mail has a one-click unsubscribe link and `List-Unsubscribe` headers. Mail comes from nowfile@nowfile.org through the existing mail package. A `changes` table (id, user_id, key, value, set_at) appended by the slot-write path records the history both features read, kept 90 days. `subscribers` (id, user_id, email, confirmed, token hash, created). A user can see the count of confirmed subscribers on the account page and nothing else about them.
5. Directory. `GET /directory` lists users who opted in, name and headline line, alphabetical, no pagination until it is needed. Add `directory` to the reserved names. The finger empty query already lists them.
6. Shortcuts recipe for Focus. `docs/shortcuts.md`: how to build two iOS and macOS Shortcuts, one that sets `Focus` to the Focus mode name over the API and one that clears it, triggered by Focus automations. Screenshots are not needed; exact actions and the request body are. Link it from the account page token section.
7. `plan` releases. A GitHub Actions workflow on tags `v*` builds `plan` for darwin/arm64 and darwin/amd64 with `-trimpath -ldflags "-s -w -X main.version=<tag>"`, attaches both plus SHA256SUMS to a GitHub Release, and `plan --version` prints the tag. `docs/install.md` gives the curl and chmod install for Mac and the `go install` alternative. Linux and Windows are later.

## Not in this phase

Last.fm or any server-side now-playing. Web push. CalDAV with authentication; a URL that needs a password is rejected with a message saying so. Any AI rewriting of calendar lines (phase 3).

## Done means

- Mike adds his calendar's ICS URL on the account page, sees the preview, enables it, and `finger mike@nowfile.org` shows `Calendar: Busy until ...` during his next meeting and nothing after it ends, with no event subject anywhere.
- A reader subscribes by email to Mike's page, confirms, and gets the next morning's digest listing the change. `https://nowfile.org/mike.rss` validates and shows the same change.
- `curl -L` of the release asset installs `plan` on a Mac and `plan --version` prints the tag.
- `go test ./...` covers ICS parsing and recurrence expansion against fixture files, busy-span merging, the preview, the subscription confirm and unsubscribe flows, RSS output, and the directory.
